# 10k guide → 1B WAIT comparison

Two sequential arms, WAIT=0 then WAIT=1, 3000 environments each, seed8 and guide seed100008. Same original 10k/1B checkpoints, own original normalizers, serial guide2/execute2, scale25, DDIM4/4, fresh noise. Original TensorRT FP16/fused analytical update implementation generalized to batches and chunked into microbatches of at most 256; both arms share this implementation and validation gates. Numerical gates include the original FP32 controller comparison, FP16 drift, and batched-vs-single independent action check.

No rendering. Maximum physics pace 30 control steps per wall-clock second in both arms. WAIT=0 continues physics with the previous absolute target while an asynchronous request is outstanding; WAIT=1 waits without advancing physics. Identical first inference before the first physics step in both arms. One global batch of all 3000 environments per two-action chunk maintains fixed model workload even after individual first episodes terminate. Discard stale actions across resets. Only each environment's first episode contributes to results. Cap 12000 control steps = 400 simulated seconds. No full-trajectory resets (TRAJ_STEPS_LIMIT=0), unchanged original video failure thresholds and randomization.

This uses actual batch-inference latency, which can be much greater than single-environment TRT latency. Thus it measures native 3000-environment deployment semantics, not an isolated emulation of the real hand's delay. Both processes of one arm necessarily share the GPU as part of the evaluator; the two arms and unrelated tasks never run concurrently. Initial observation, demo assignment, initial frame, and actor root states are saved and compared exactly before results are marked complete.

Outputs: wait0/ and wait1/ contain first-episode records, initial states, numerical validation and timing logs; comparison.json/md summarize the result. Known exit139 during Isaac Gym teardown is accepted only if all 3000 unique first episodes and the final timing summary are present. No automatic retries. CPU scheduling and syntax checks passed before launch.
