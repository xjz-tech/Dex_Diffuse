# h8 与旧 1B／10B 的 3000 环境自主转动对照

三组采用 seed42 的同一批 3000 个原生随机初态，示范 000–149；无外力，普通 prior，EMA 权重，DDIM4，每次执行 2 个控制步。每条只取首轮，最多观察 900 控制步；上限处未失败的记录为右删失。原生失败阈值和目标更新沿用 `eval/xjz_test.sh`，不把原生 failure 直接称为物理掉落。

10B 复用 `../20260927_prior3000_joint_turn/seed42` 的完整记录。1B、h8 使用同一份旧 10B 仿真源码副本，仅把检查点加载和策略规格校验扩展到 h8 的 horizon8／future5；旧 1B／10B 为 horizon12／future9。10B 新路径文件的 SHA256 与存档 `da56ef248a4ccb7755619630590c26c1f19f1c42c9c0cc541116ecd488b81d3a` 一致，1B 新路径 SHA256 与历史配对报告的 `ad0bf60d9fe743161916c55fee36a1b6b13840757baaca2136dcfc3b5b597302` 一致。h8 SHA256 为 `8149bb20be60f0260fe0f5e44240f6b657864da3eacf09c479215aea5412fc46`。

旧 1B 虽有 10,000 个配对初态的长时记录，使用的是另一随机外力设置及每 seed 2500 个环境，不能与本次旧 10B 的 seed42／3000 环境无外力转动记录逐环境比较，因此在本目录补跑。h8 与旧 10B 的 27 类初始化字段已逐值核验一致；三组完成后 `analyze_comparison.py` 会再次核验两组初态并汇总。

第一次 h8 尝试在用户继续消息到达时中断，部分记录保留在 `seed42_h8_interrupted_01`，不参与统计。正式运行从同一 seed 完整重启，没有拼接记录。
