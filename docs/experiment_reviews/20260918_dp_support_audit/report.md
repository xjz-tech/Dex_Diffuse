# DP 单步目标边界与随机化审计

日期：2026-09-18。只检查代码、归档配置和纯离线模型输出；未启动仿真，未操作硬件，未改动训练或评估协议。

## 主要结论

0.09 rad 是采集控制器的结构性目标增量边界，不能理解成关节实测位移上限。采集配置为 clipActions=1、actionScale=0.1、actStyle=flat_hora；动作先经过 0.1 死区，再增量累加到上一目标，因此最大增量是 0.1*(1-0.1)=0.09。DP 则生成绝对 target_after；普通 epsilon MSE、绝对关节范围裁剪都不提供相邻目标增量约束。

输入来自训练源的真实四帧历史时，离线预测同样大量超过 0.09。因此环境随机化、初始化历史替换和闭环分布漂移都不是产生这种超限的必要条件。增加 DDIM 步数至100没有解决这组样本的超限；这不等于证明所有采样器和步数在闭环中表现相同。

## 离线实验

- 模型：`/home/carus/data_usb/obs_4-66.ckpt`，严格加载 EMA，未 salvage。
- 布局：4帧×66维观测，horizon=12，可用未来9步；本诊断只分析前2步，不执行动作。
- 数据：`/home/carus/Data/exp_data/exp_data_mmap_obs4_h12`，固定 seed=20260918，按转移索引抽取256个训练划分内窗口，排除episode边界，历史 target_before 从同episode的前一帧 action 重建。局部10k数据既有审计已检查 target_before 与上一 action 一致。
- 观测：`[q, target_before, target_before-q]`。不同条件、DDIM步数使用配对初始噪声。无guide。
- 超限阈值：`abs(delta)>0.09+1e-6`，排除浮点舍入。每个窗口一次采样，不能当作整个数据集的精确总体比例。
- 溯源限制：checkpoint记录原训练路径 `/share/generalvision/xiejunzhe/Data/exp_data`；本机训练源是 `/home/carus/Data/exp_data`。本次未取得远端数据hash来独立验证副本完全一致。

DDIM4 的第二预测目标减第一预测目标，任一关节超限比例为63.67%，因此现象也存在于同一次生成chunk内部，不只是重规划拼接点。DDIM4首步最大增量为0.13331 rad。

同一批标签首步中约14.95%的关节增量紧贴0.09边界（误差<1e-6）；约36.31%为零。边界堆积意味着很小的拟合偏差就可能越界；同时22个关节取“任一超限”会放大步级发生率。这是与统计相符的解释，不是对每个越界样本成因的证明。

初始化历史替换也明显影响模型，但并没有在此样本上提高超限率：DDIM4下，真实历史的前两步相对记录动作MAE=0.01326；重复当前观测为0.04477；重复当前观测且把target设成q、residual设成0为0.06702 rad。后两个条件的首步任一关节超限率分别为7.42%、10.94%。MAE只是相对这条记录的差异，多模态动作下不等于任务错误。

## 原生初始化并非恢复RL训练轨迹

`eval/sim_eval.py` 使用原始demo随机帧初始化，然后重复当前观测填满历史。任务reset将关节、物体速度清零，并令当前及上一目标等于初始化关节角。因此“同一demo的一帧”不保证等于RL rollout里的状态或四帧条件。即使确实恢复同一关节角，速度、目标残差、物体接触、动力学参数和历史仍可能不同。rollout后续会进一步受模型误差影响。

本次离线结果已经隔离掉这些因素，所以不能把初始化差异直接归为全部超限的根因。

## 数据质量判断与优先级

1. 优先处理动作表示与训练标签硬边界不一致：生成绝对目标不保证0.09增量。可比较有界增量表示或把同等速率约束加入执行；这是实验变量，不能把限幅后的闭环效果直接假定为更好。
2. 专家动作存在零点及饱和边界堆积，值得检查饱和持续时间、动作反向频率、不同速度风格覆盖。边界堆积本身不证明专家动作无效。
3. 随机化中最值得做受控对比的是高摩擦尾部与恢复系数，而不是统一关闭全部随机化。需要按物理参数分桶比较专家成功、动作饱和、DP拟合和恢复行为，才能判断是否过强。
4. 数据已经做失败过滤：manifest记录至少达到2个目标，失败episode裁剪到最后一次成功。不能说“完全没有过滤失败”。但这种过滤可能使保留下来的有效随机化分布偏向易成功条件，并削弱失败边缘恢复状态覆盖；需统计验证。
5. 10k guide只有20个完整episode，9999步，不等于10000个独立场景。当前full源约1亿转移、159574个保留episode，metadata只列bulb2；“1B”是现有模型称呼，本审计不把它解释成10亿转移。DexGen用了多对象、多任务、多种快慢风格，不能只比较总步数。
