## 数据与片段

检查了80个episode，共44,142帧；state/action为31维，object为16维，长度对齐且数值有限。obj_state不是上一个数据集中的全零占位，而是有效的齐次4×4矩阵。检查数值和front/wrist图像后，选择：

| 来源 | 状态帧 | 动作帧 | 记录的物体起止世界竖直角 |
|---|---|---|---|
| episode51 | 105–180 | 105–179 | 77.67° → 33.23° |
| episode53 | 90–165 | 90–164 | 77.60° → 25.73° |

两段从已离桌的抓持开始，结束时尚未接触灯座。没有把插入灯座过程作为空中换握结果。早期候选episode37/63中的部分物体轴数值与图像/任务阶段不一致，未采用那些片段。

取state后22维为初始手关节角，action后22维为引导reference。按现有dex_sim_bench读取器的约定，将前9维解析为基座系TCP位置及旋转矩阵前两行，将obj_state按行重排为4×4，再用 `inverse(T_base_TCP) @ T_base_object` 生成手腕相对物体位姿。将该相对位姿放到每个原生仿真wrist上，wrist本身不改。

**坐标标定限制：**目前沿用现有代码对该格式的约定；没有收到独立标定文件来确认TCP与仿真手根坐标完全重合。原生评估手URDF与现有真机回放手的fixed-base mounting相同，灯泡资产网格哈希也一致，但这不能替代数据采集系统的外参标定。具体假设和哈希见 `reference/verification.json`。真实机械臂移动不回放：两段真实TCP位移约11.2/12.0 cm，旋转约27.3/24.9°。因此额外计算了物体相对手腕的转向误差，不将世界竖直角当作唯一动作相似性指标。

“手内转向指标”在扩展结果分析前明确记录为：全程无原生failure、末15步与记录的**手腕相对末态灯泡轴**误差≤30°、动作过程中手腕相对灯泡轴变化≥30°。这是新增的参考动作相似性指标，不替代原生failure判定。此前的世界横转竖指标仍单独保留：静态结束距竖直60–120°，末15步≤30°（及更严格≤20°）且无failure。本次均为0。

## case467

- 来源episode53，初始q为state90，reference为action90–164。
- 初始物体相对**按行解析的记录位姿**平移 `[+0.02,+0.02,-0.02] m`，绕手腕局部X轴增加15°；使用该环境原生随机wrist和其他物理随机化，噪声seed44。
- 旧代码写入张量的候选位姿到静置结束记录之间，物体中心相差约8.26cm；后来发现物理场景没有按该候选位姿起步，不能把这项差值全解释为物理接触造成的位移。
- 动作起点/动作终点/保持终点距世界竖直：44.21° / 12.39° / 16.87°。
- 手腕相对灯泡轴变化54.89°，保持终点距记录末态灯泡轴26.62°。
- 实际视频中保持住灯泡；碰撞网格最低点在动作+保持期间距离桌面至少约12.3cm，排除了靠桌面支撑转正。此项是辅助几何复查，不改变环境failure规则。
- 同初态复跑：27项初始化存档完全一致；该case的q、qd、物体位姿/速度、wrist、命令、实际目标、接触力、原生目标索引、failure和施加外力等完整记录逐项一致。只验证同初态复现，不代表多seed稳健性。

[原视频 / 旧张量写入候选姿态 / 静置末态并排图](initial_pose_diagnostic/case467_source_import_settled.png)与[按列 / 按行 / 扰动候选 / 静置末态四列图](initial_pose_diagnostic/case467_rotation_parser_comparison.png)显示了数据坐标差异；图中的候选姿态不能证明 PhysX 实际从该姿态开始。数值和导入设置顺序审核见[诊断说明](initial_pose_diagnostic/README.md)：旧第一步相差7.54cm主要是位姿写入未应用的伪迹；6D旋转按行与按列解析的结果相差约20cm、90.6°。TacMP目录内的episode53与当前数据逐字节相同，相关真机接口按行写入6D，但未找到该episode实际采集时的外参档案。
