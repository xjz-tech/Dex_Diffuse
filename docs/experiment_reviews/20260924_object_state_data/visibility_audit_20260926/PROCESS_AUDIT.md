# 2026-09-26 复审：为何视频中看不到灯泡，以及原批次的有效性

结论：物体确实被创建和导入，但旧录像遗漏了初始化后的静置阶段，固定近景又看不到落到桌面的灯泡。更严重的是，初始支撑环境与真机不同，且完整真机任务需要移动 wrist 和灯座承接；因此撤回将先前末帧 `0/80` 指标解释为真实翻转/放置成功率、或 prior 能力结论的做法。原始数值保留为这套不等价仿真设置的记录。

## 已直接复现的事实

为 episode 0、2、28、51 重新录制原始动作直接仿真，增加导入瞬间、全部 60 个静置控制步和固定全景相机。没有改变动作、初始化、物理参数或原生 failure 协议。四条完整数值轨迹与旧 `full/direct/trace.json` 逐项相等。

- 四条导入画面都有灯泡。episode 0 在静置阶段落到桌面；另外三条在动作过程中落到桌面。末端全景均可见桌面上的灯泡，原近景同时只剩手。
- 以网格最低点距仿真桌面不超过 5 mm 为辅助几何标志，四条首次接近桌面的记录分别是：ep0 静置第 7 个控制步；ep2 动作第 199 个控制步；ep28 动作第 115 个控制步；ep51 动作第 55 个控制步。这是网格几何检查，不代替接触传感器。
- episode 51 原始动作末端的“轴距竖直 2°”，全景可见是灯泡已经落到桌面后立着，不能计为手中成功翻转。
- 新诊断视频是原始动作直接仿真，左边保留原近景，右边是全景。每条导入瞬间画面停留 1 秒，其余按 30 Hz 播放。四条共 2691 帧、89.7 秒。

## 流程问题

1. **录像漏掉了决定起始状态的 2 秒。** 旧 `compare_corrected_rollouts.py` 先执行 60 次 `step(held, 'settle', ..., False)`，随后才录像。静置期间 reference 尚未前进，物体却已经在自由物理中运动。ep0 在动作开始前偏离导入位置 25.25 cm。旧首帧不能称为数据导入初态。

2. **“横着”未保证“已经离桌并被稳定抓住”。** `prepare_all_full_episodes.py` 优先选择估计离桌 ≥1 cm 的帧，没有这种候选时回退到普通横向帧，共 37 条回退。导入只保持手与物体的关系，没有同步变换桌面。以下高度用同一网格和已保存位姿估算，真机桌面高度仍是既有近似值：

   | episode | 真机网格最低点离桌 | 仿真导入时最低点离桌 |
   | --- | ---: | ---: |
   | 0 | 0.044 cm | 24.27 cm |
   | 2 | 2.50 cm | 23.32 cm |
   | 28 | 0.253 cm | 25.35 cm |
   | 51 | 9.84 cm | 27.62 cm |

   80 条导入时的仿真网格离桌范围为 22.46–27.85 cm。不能把依靠真实桌面支撑的近桌帧直接当成仿真的悬空稳定抓握。静置后有 25/80 条的位置偏移超过 5 cm；23/80 条触发原生 failure。这两个统计是不同条件。

3. **已有初始化质量检查未被用来限制结论。** 原分析中的 `calibration_gate` 要求：静置无 failure、首个记录步位移 <5 mm、60 步静置后位移 <1 cm、旋转变化 <10°。只有 ep8、44、63、74、77 共 5 条通过。该检查也不是实物标定的证明，但这已经足以阻止把整批当成验证通过的抓握复现。

4. **完整真机动作与模拟场景不等价。** 用户要求保留原仿真 wrist 设置，因此本批 wrist 固定；真机腕部从选中起点到末帧移动中位数为 17.67 cm。原生场景只创建手、桌子和灯泡，没有对应的灯座。真实尾段的移腕、放置、松手缺少模拟承接条件，末帧位置误差不能直接作为翻转成功率。`轴角≤45°且位置误差≤10 cm` 的 0/80 只是该不等价设置下的描述性计数，应撤回其任务成功率含义。

5. **坐标与接触标定仍未被独立证实。** `reference/verification.json` 明确把数据 TCP 与手 URDF root 一致视为假设；object pose 到当前物体网格的标定同样没有在这次批处理中通过相机/接触约束独立验证。网格与另一套 replay 使用同一文件，不等于它与真机抓握几何吻合。不能仅凭这些结果断言“只是灯泡尺寸”或“prior 动作太小”。当前物体实例还继承了原生随机化 scale=0.987454，不能说是严格 1:1 物理复现。

6. **原生 failure 的参考目标不是当前外部 episode 的逐帧 object state。** 初始化选了一个最接近的原生 000–149 示范作为环境 goal，随后仍用原生目标更新。外部 reference 只引导手动作。这遵守现有原生 failure 协议，但该信号不能称为外部 Object_state_data 轨迹的逐帧跟踪成功/失败标签。

## 已排查通过的部分

- 80 条的 saved reference 手关节、动作、世界物体位姿分别与各自源 `state.npy`、`action.npy`、`obj_state.npy` 对应切片一致。80 条导入 snapshot 的手关节及物体世界位姿，与各自 reference 按保存 wrist 变换后的数值一致。没有发现复用 ep53 物体初态、漏创建灯泡或选错 episode 文件。
- 全部 240 条质量与摩擦 readback 正确：0.17 kg，手和物体 friction 都为 2.2。原生 failure 阈值未被替换。初态中 22 条的初始保持目标有少量关节限位裁剪，最大 0.0417 rad；这需记录，但不足以单独解释所有失稳。
- reference 推进使用当前动作索引 `j`，exec2 执行后前进 2 个插值后目标，exec1 前进 1 个。未发现反复回到同一个 a1–a2 的索引错误。
- 所谓每条的“27 项初态一致”，仅证明同一 episode 内三种方法一致；它不能证明真机到仿真标定正确。四条新全景录像与旧数值轨迹完全一致，同样只证明补录没有改变实验。
- 记录中的一个 step 实际是一个约 1/30 秒控制步（`dt≈1/60`、`controlFrequencyInv=2`，每次 simulate 内 `substeps=2`）。先前把首个记录步称为“第一物理步”不够准确。

## 已完成修正与后续评估边界

新增 `--audit-recording`，记录导入、静置和全景；原始默认实验设置未改变。已生成可复查的视频、截图、80 条源数据/支撑高度审计和四条录像轨迹审计。旧报告及汇总文件标注了有效性更正，原始数值保留。

下一轮要先逐条确认真正的离桌横抓帧和静置后的接触状态，对不具备有效起点的 episode 明确标记；验证 TCP、物体网格坐标和抓握接触，再评估翻转段。若继续保持固定 wrist，应把翻转评价与需要腕部运动、灯座承接的后续放置/松手分段报告；完整尾段可以继续播放，但不能共用同一个成功判据。在这些条件验证前，不再把旧批次作为 prior 成功率结论。
